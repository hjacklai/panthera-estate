# pantheraestate.com

Marketing site for **Panthera Bertam**: 19 freehold homes (3 bungalows, 16 semi-detached) around a shared central park in Bertam, Penang. Developed by Panthera Development Sdn. Bhd.

Static HTML / CSS / JS, no build step for the site itself; the `/ms/` and `/zh/` pages are generated by `scripts/build_lang.py` (Python 3) before every commit, see Release steps. three.js comes in through an importmap from jsDelivr. GitHub Pages serves `main` on the custom domain (`CNAME`), so a push to `main` is live.

## Structure

- `index.html`: the live page (English, `/`). A one-screen 3D app, with a scrolling-page fallback for bots, no WebGL, data saver and `?hero=scroll`.
- `ms/index.html` (`/ms/`, Bahasa Malaysia) and `zh/index.html` (`/zh/`, Chinese): GENERATED from `index.html` and the I18N strings in `app.js` by `scripts/build_lang.py`, with the text already translated so search engines and AI crawlers (which run no JavaScript) see it. Never edit them by hand.
- `app.js` (i18n EN / BM / ZH, page features, Leaflet map), `styles.css`, `home-toggle.js`, `topo-flow.js`.
- `sw.js`: service worker (keeps `?v=` URLs between visits). `version.txt`: the live build number.
- `404.html`, `robots.txt`, `sitemap.xml`, `llms.txt`, `llms-full.txt`, the Google site-verification file.
- `assets/`: images. `assets/fonts/`: the self-hosted Google fonts (`fonts.css`).
- `walkthrough/`: the 3D.
  - `hero-boot.js` (entry and preloads) and `hero*.js` (the landing estate), `explore.js`, `gallery.js`.
  - `walk.js` with `index.html`: the stand-alone walk page.
  - Builders: `estate.js`, `furniture.js`, `car.js`, `tropical.js`. Model data: `*.json`.
  - `pack.js` and `bake/`: the baked estate pack. `hd.js` and `hd/`: photo textures and skies (only the files `hd.js` loads are kept). `audio/`.
- `walkthrough/tools/` (gitignored, kept on Drive): bake page, bake server, previews, check scripts.

## Run locally

`python walkthrough/tools/bake_server.py` (or `python -m http.server 8766` from the repo root), then open http://127.0.0.1:8766/.

The service worker stays off on 127.0.0.1 unless the URL has `?sw=1`. Useful flags: `?hero=scroll`, `?nosw`, and on the walk page `?home=bungalow` and `?hd=0|1k|2k`. `walkthrough/hero-boot.js` lists the other `?hero=` test flags.

## Language pages (/ms/ and /zh/)

- The same page at three addresses. All three carry `<base href="/">`, so every relative URL resolves from the site root whatever the address; `app.js` keeps in-page `#links` on the page.
- The address wins on load (`/ms/` is BM, `/zh/` is Chinese; `/` uses the saved choice as before). The language button switches in place (no reload) and moves the address with `history.replaceState`, keeping `?query` and `#hash`.
- Text, title, description and share-card strings live only in `app.js` (`I18N`, including the `meta.*` keys). The hreflang block in `index.html` and `sitemap.xml` lists all three.

## Release steps

Do these on whichever computer you push from, in this order:

1. Make the change (index.html, app.js, any file) and bump its `?v=` everywhere it is referenced; for a new build bump the three numbers below.
2. `python scripts/build_lang.py` writes `ms/index.html` and `zh/index.html` again. Run it after ANY change to `index.html` or to the I18N strings in `app.js`, and after every `?v=` or build bump (the pages carry the same stamps and build number). It must run last, after the bumps.
3. `python scripts/build_lang.py --check` changes nothing and exits 1 if either page is missing or out of date (and prints warnings if `index.html` and `I18N.en` disagree). Run it before every commit.
4. Commit the two generated pages together with the change. Preview locally and get the owner's OK before pushing.

## Versions and caches

- Every changed file gets a new `?v=N` wherever it is referenced. `sw.js` keeps `?v=` URLs on the visitor's device, so a file changed without a bump is never seen again.
- A new build bumps three numbers together: `V` in `walkthrough/hero-boot.js`, `B` in `index.html` and `version.txt`. Open pages reload once when `version.txt` differs. `VER` in hero-boot.js holds the per-file hero module stamps.
- Rebake: bump `BAKE_REV` in `walkthrough/versions.js` and `BAKE_Q` in `hero-boot.js`. `BAKE_VER` renames the pack files.
- A texture or sky replaced under the same name: bump `TEX_REV` / `SKY_REV` in `walkthrough/hd.js` (and hero-boot.js's golden-sky preload with `SKY_REV`).
- `sw.js`: rename `CACHE` to drop every kept file; `OFF = true` is the kill switch.
- `sitemap.xml` `lastmod` is the push date (the `/`, `/ms/` and `/zh/` entries move together). On a content change, move these to the same date: `dateModified` in the JSON-LD of `index.html` (WebPage and RealEstateListing; build_lang.py carries it to `/ms/` and `/zh/`) and of `walkthrough/index.html` if that page changed, and the `Last updated:` line in `llms.txt` and `llms-full.txt`.
- A stale `/ms/` or `/zh/` page cannot loop: the version check reloads at most once per build per tab session (`sessionStorage` `pb-build`), but run `--check` so they never go out of date.

## Bake workflow

1. `python walkthrough/tools/bake_server.py`
2. Open http://127.0.0.1:8766/walkthrough/tools/bake.html. It writes `walkthrough/bake/estate.<BAKE_VER>.*`.
3. `python -I walkthrough/tools/check_pack.py` checks that the inputs match and every pack file exists.
4. Bump `BAKE_REV` and `BAKE_Q`, then commit `bake/` together with the source change.

## House rules

- No em-dash characters anywhere.
- No people in any imagery.
- Preview locally and get the owner's OK before pushing.
- If two pushes jam GitHub Pages, request a fresh build (`POST /repos/{owner}/{repo}/pages/builds`).
